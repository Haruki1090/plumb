# plumb v0.10.0 — lead a queue

An owner rarely hands over a task. They hand over a queue: "review the PRs", "implement what is
assigned to me, one at a time". Nothing in plumb took that shape. The pieces existed — `plumb:graph`
for decomposition, `fan-out` for independence, `running-a-plan` for the gate and the rework cap,
`plumb:pr-review` for judgment, `autonomous-run` for crossing a night — but the route between them
was rebuilt by hand every time, and the same failures came back: an issue implemented after its fix
had already merged into the integration branch, a second PR opened for work already in review, two
lanes rewriting one file, and approvals relayed without being read.

`plumb:lead` fixes the route. The main session is the coordinator and writes no lane code. It reads
the queue from the tracker into a decision log, drops what already landed, gives each remaining item
a worktree and a visible tab through `pane.driver`, and drives each lane through a separate review
seat and final-commit checks to a ready PR. Only irreversible actions, product calls, out-of-range
approvals and real dead ends go up to the owner, in one batch.

## Compatibility

Additive. No existing playbook, principle or skill changed behavior. The skill names no tool:
where lanes run comes from `role.bulk`, `role.judge` and `pane.driver`, and an unset `pane.driver`
is a visible skip.
