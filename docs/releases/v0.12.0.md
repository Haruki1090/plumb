# plumb v0.12.0 — from install to working

An end-to-end audit of the install path (Claude Code and Codex, on a fresh home, stock macOS bash 3.2
and python 3.9) found no broken install, but it did find places where the installed plugin did not
behave as its documents promised. This release fixes them, together with a tighter router.

## What changed for users

- **PR review reaches its own agents.** `plumb:pr-review` now launches `plumb:pr-refuter` and the
  other bundled agents by their plugin names. Before, the bare names did not exist on a fresh
  install, and on a machine with personal agents of the same name they launched those instead.
- **Cleanup no longer calls unmerged work safe.** `plumb-worktree-audit` marked a worktree whose PR
  was closed without merging as `safe`, and a worktree path with a space was reported clean
  whatever it held. Both fed the worktree-cleanup playbook.
- **Codex setup keeps your project config.** `--project --force` replaced any existing
  `.codex/config.toml`, including your MCP servers. It now replaces only a file plumb wrote.
- **Doctor tells the truth on a new machine.** No NG for a directory that appears after the first
  session, for a multi-word role command, or twice for a missing gh.
- **The router is shorter.** Artifact lifecycle rules live in `docs/artifact-lifecycle.md`, and the
  playbooks that pointed at removed sections now point at the current ones.

## Compatibility

- `plumb-path run` now resolves to the main worktree's `.plumb/run/`. Ledgers written from a linked
  worktree before this release stay where they were.
- A project `.codex/config.toml` installed by an earlier release is still recognised as plumb's.
