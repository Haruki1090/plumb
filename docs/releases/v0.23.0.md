# plumb v0.23.0 - routing: Explore on the model you name, an agents table, a price correction

A built-in Explore subagent ran on the main session's model, whatever `role.explorer.model` said, and
`views` could not show which agent types ran on which model. A cache-read price in the ledger was also
wrong.

## What changed for users

- A `PreToolUse` hook on the `Agent` tool (`scripts/agent-route.py`) gives an Explore call that names no
  `model` the alias in `role.explorer.model` (`sonnet`, `opus`, `haiku` or `fable`). Any other call is
  left as it was, and the hook writes no permission decision: it changes the model, not whether the
  call is allowed. The environment variable `CLAUDE_CODE_SUBAGENT_MODEL` reaches other subagents that
  name no model, but not the built-in Explore (measured on Claude Code 2.1.322), which is why a hook is
  needed.
- `plumb-ledger views` writes an agents table, `agents.md` and `agents.csv`: one row per role, agent
  type and model, with threads, requests, cost, share, and the median context of a thread's first
  request and of its largest. `plumb:retro` reads it.
- `plumb-bootstrap --explorer-model`, `--implementer-model` and `--bulk` write the role keys, and
  `plumb-doctor` reports three more lines: `role.explorer.model`, `role.implementer.model` and
  `CLAUDE_CODE_SUBAGENT_MODEL`.
- `docs/role-map.md` explains how a subagent's model is decided, defines the design role, and says not
  to switch the main model in the middle of a session.
- `assets/prices.json` has a new version, `2026-11-10`, with `claude-fable-5-2` ($8 input, $0.20 cache
  read, $40 output per million tokens) and a corrected cache read for `claude-sonnet-5-5` ($0.10, not
  $0.20). The prices were checked on 2026-11-10 against the Claude API pricing page.

**This changes the cost of rows that already had one.** Sonnet 5.5 rows from 2026-08-22 on cost less by
their cache-read share (half of what they showed). The new version has the same `effective_from` as
`2026-11-09` and is listed after it, so it is the version in effect for every moment `2026-11-09` was:
every row from 2026-08-22 on now carries `price_version` `2026-11-10`. A warehouse that merges
`plumb-ledger records` on `id` replaces those rows when it loads again. Sonnet 5.5 rows before
2026-08-22 keep their original version and cost.

## Do you need to do anything

No. The hook does nothing while `role.explorer.model` is unset. If you set it to something that is not
an alias, such as a model's full ID, the hook does not write it and `plumb-doctor` reports NG; change
the value to one of the four aliases. To reload a warehouse with the corrected costs, run `records`
for the period from 2026-08-22 on and merge on `id`.

## Verification

`scripts/test-agent-route.py` runs the hook with JSON on stdin and a throwaway config. It checks that an
Explore call without a model gets each of the four aliases, that the output is the whole input plus
`model` under `hookSpecificOutput` with no permission decision, and that nothing is printed (exit 0) when
the call already has a model, is a general-purpose or Plan call, when the key is unset, when the value is
not an alias, and when `tool_input` is missing or stdin is not JSON or is empty.
It also runs the `hooks.json` command with the plugin root replaced by a directory that does not exist and checks it exits 0 with nothing on stdout (the command ends in `|| true`, because a `PreToolUse` command that exits 2 stops the tool call).
`scripts/test-ledger-cost.py` checks that `hooks/hooks.json` holds the `Stop` hook and the `Agent`
`PreToolUse` hook and no other event, and that both scripts are executable. The existing suites
`scripts/test-ledger-views.py` and `scripts/test-bootstrap.py` cover the agents table and the new
bootstrap options, and `scripts/check-harness.sh` and `scripts/selftest.sh` pass.

The hook was also run in Claude Code 2.1.322, headless (`claude -p`, the plugin loaded with
`--plugin-dir`, the main session on one model and `role.explorer.model` naming another), and the
models were read from the run's `modelUsage`: an Explore call with the key set ran on the named
model; with the key unset it ran on the main session's model; a general-purpose call with the key
set was not changed. The hook writes `updatedInput` without a permission decision, and that alone
took effect.
