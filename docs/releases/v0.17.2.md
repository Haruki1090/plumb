# plumb v0.17.2 — doctor checks that Codex is logged in

`plumb-doctor` marked a role routed to Codex `ok` as soon as the `codex` command was on PATH. In a
cloud session, where Codex is logged in per session, it read `ok` while logged out, and the judge
failed on its first call. `plumb-bootstrap` already checked the login; doctor did not.

## What changed for users

- A role whose command is `codex` (`role.judge`, `role.bulk`) is `ok` only when `codex login
  status` succeeds, and the line says `(logged in)`. Logged out is `NG` with the login command.
  What `codex login status` prints is never shown.
- `docs/cloud-setup.md` says what the judge's `ok` means for Codex.

## Compatibility

No config key or command changed. A logged-out Codex role that used to pass now makes doctor exit
1. Other role commands are checked as before.

## Verification

Harness check and the full selftest passed, including new cases for a logged-in and a logged-out
Codex stub.
