# plumb v0.18.0 — the ledger reads the branch from the reflog

The work ledger assigns each request to a branch, and the branch to a pull request. It took the
branch from the transcript's `gitBranch`, which Claude Code fills with the branch of the directory
the session was launched in; it does not follow `cd`. Measured with `claude -p`:

- launched outside the repository, then `cd` into it: every request said `HEAD` (`unknown`);
- a branch switched away from and deleted in the same turn: gone at capture (`unknown`);
- launched in the main checkout, then `cd` into a worktree: attributed to the main checkout's branch.

On the owner's store, 236 of 780 requests of 2026-10-31 (30% of cost) were `unknown`.

## What changed for users

- A request's branch is the one its directory's HEAD reflog names at the request's time
  (`attribution_source = reflog`). Later renames are followed, so the record carries the name the
  pull request uses; a branch deleted since keeps its name.
- Codex requests get a branch the same way.
- When the reflog cannot be read, the old rules apply (`worktree_at_capture`, `transcript`).

## Compatibility

No config key, command or record field changed; `attribution_source` gains the value `reflog`.
Records already in a store keep their old values, and reports read them as before.

## Verification

The ledger cost suite (new cases for each measured case, renames, detached HEAD and tags, a rebase,
Codex, the same-second rule and the unreadable-reflog fallback), the harness check and the full
selftest passed.
