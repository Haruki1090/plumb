# plumb v0.9.0 — The remaining Software Factory levers

Four levers from Uber Engineering's "Running a Software Factory Efficiently at Uber Scale" that
plumb did not yet carry, each attached to a term the audit already prints.

`plumb-session-audit` gains `FIRST-REQUEST-OVER`: a session whose first main-chain request
exceeds `--first-threshold` (default 50,000 tokens) is flagged, so the fixed prompt that every
later request re-sends becomes a measured term rather than a feeling.

`plumb-prompt-weight` lists the user-controlled parts of that fixed prompt — instruction files,
the memory index, session-start hooks, each enabled plugin's skill and agent listing, user skills,
MCP declarations — with bytes and a byte-derived token estimate. It never executes a hook and
never prints file contents; the runtime's own prompt and tool schemas are out of its sight and it
says so.

`plumb-statusline-cost` prints the runtime's running cost estimate as one status-line segment.
With `cost.jpy_per_usd` it adds yen; with `cost.session_budget_usd` it colours the figure at the
50 / 80 / 100 % bands, so the nudge arrives during the turn instead of on next month's bill.

`role.explorer.model` is a config key for the explorer role's model. Unset inherits. The table
saying where effort goes up now lives in `docs/role-map.md`; the graph reference and the PR-review
skill point at it instead of restating it.

## Compatibility

No changes to installation commands. Existing audit JSON gains one flag, one threshold and one
per-session field; consumers that ignore unknown keys are unaffected. Nothing changes model
placement unless the owner sets the new key.

## Verification

Full harness check and selftest (101 passing checks together) passed before publication, including the new prompt-weight,
statusline-cost and explorer-key assertions.
