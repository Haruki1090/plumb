# plumb v0.21.0 - ledger: every runtime on the machine

`plumb-ledger capture` recorded Claude Code requests from the Stop hook and nothing else. Codex had a
parser that nothing called (and `--transcripts` read only the direct files of one directory, while Codex
writes `sessions/YYYY/MM/DD/rollout-*.jsonl`), OpenCode had no adapter, and a cloud container that was
reclaimed lost every Codex row that had not been exported. One place for time, cost and model per task,
across the CLIs on a laptop and in cloud sessions, needed all of them captured.

## What changed for users

- **`plumb-ledger capture --sweep`** captures Codex (`$CODEX_HOME/sessions` and `archived_sessions`,
  recursively) and OpenCode (its SQLite database) from their default locations. `ledger.runtimes`
  picks the runtimes (default `claude,codex,opencode`); a location that is not there is `missing`, not
  an error. Claude is not swept: its Stop hook captures it.
- **OpenCode** is a runtime. The database is opened read-only and only two tables and the columns
  needed are queried; the credential and account tables are never named. A row is one completed
  assistant message: `output` is visible output plus reasoning, the cache write goes to
  `cache_write_5m`, the model is `<providerID>/<id>`, and a subagent session is a `subagent` row of
  its root session. Usage OpenCode keeps only in session totals (title generation, compaction) is not
  captured.
- **The sweep stays cheap.** A Codex rollout whose size and mtime are unchanged is not opened; one the
  normalizer refuses is counted as `failed`, logged once per change and not retried until it changes. OpenCode reads
  from a watermark with a ten-minute lookback.
- **The Stop hook** runs the sweep after the Claude capture when `ledger.capture = on`; a failure in it
  never fails the capture or the hook, and with `ledger.export = on-stop` the swept sessions are
  exported at the end of the turn.
- **A laptop without a Claude session running** can use the scheduled job in `docs/ledger.md` (a macOS
  LaunchAgent or a `crontab` line running `plumb-ledger capture --sweep && plumb-ledger export` every 15
  minutes). plumb does not install it.
- **Prices:** `opencode/deepseek-v4.1-flash-free` costs 0 (OpenCode's free tier). A model can carry its own
  `checked` and `source`. Codex models stay unpriced, their cost unknown, until the provider's list price
  has been checked against the provider's own page.

## Compatibility

The allowlist is unchanged, and so is every existing record and store ref; `opencode` is a new value of
`runtime`, which store refs, pending and exported files, `report` and `views` already key on.
`remote_session` of Codex and OpenCode records is set only with `CLAUDE_CODE_REMOTE=true` and is `null`
elsewhere. `capture --runtime codex --transcripts <dir>` now recurses; for Claude it does not. Without
`--sweep` and without the hook, behaviour is as before.

## Verification

`scripts/test-ledger-cost.py` gains cases for a recursive Codex `--transcripts`, the sweep index
(an unchanged file is not opened, a grown one is read from its offset, a refused one is counted once and
not retried, a moved one adds nothing), an OpenCode fixture built in the test with a decoy credential
table (field mapping, a streaming message, subagent and cycle roots, conflicts, the watermark window and
a restore, read-only access with the file's bytes and mtime unchanged, a missing table failing OpenCode
only), `remote_session`, `ledger.runtimes`, missing locations, the hook path (a failing sweep leaves one
log line and the Claude rows are written) and the prices. The existing ledger suites, the harness check
and the full selftest passed.
