# plumb v0.23.2 - watch: a new version replaces an old watch

`plumb-ledger watch` started by a session-start hook exits when another watch holds `watch.lock`. After
an upgrade that other watch was the old version, so it kept recording with the old price table.

## What changed for users

- `watch` writes `{"pid": ..., "version": ...}` into `watch.lock` once it holds the lock.
- A `watch` that cannot take the lock reads it. If the holder's version is older than its own, it sends
  the holder SIGTERM, retries the lock for up to 10 seconds, and on success prints
  `watch: replaced <old> (pid <pid>) with <new>` and carries on as the watch for the ledger directory.
- A holder of the same or a newer version, or a lock that is empty or unreadable, is left running and the
  second `watch` exits 0 with "already running", as before.
- `plumb-doctor` run inside a repository that has a project contract (`.plumb/project.toml`) said
  "selftest is failing", because the selftest cases that narrow `PATH` also read the contract of the
  directory they were started from and could not find `node`. `scripts/selftest.sh` now changes into its
  own sandbox first, so the result no longer depends on where it was called from.

## Do you need to do anything

A `watch` of 0.23.1 or earlier writes nothing into the lock, so 0.23.2 cannot tell it apart and will not
replace it. Stop it once (find it with `ps aux | grep "ledger.py watch"` and kill that pid); the next session
start runs the new version, and later upgrades replace it by themselves.

## Verification

- `python3 scripts/test-ledger-cost.py`: two new cases. A `watch --as-version 0.0.1` holds the lock; a
  normal `watch` exits 0 with "replaced 0.0.1" and the old process has ended. A `watch` of the same
  version holding the lock is left running and the second one reports "already running".
- `PLUMB_SELFTEST_QUICK=1 bash scripts/selftest.sh <plumb root>`, started from inside a repository with a
  project contract that names `node`: failed in two doctor cases before the change, passes after it.
- `bash scripts/check-harness.sh` passes with no machine-local private token list (`PLUMB_PRIVATE_TOKENS`
  pointing at an empty file); the hits that list gives are the same on the base.
