# plumb v0.19.0 - verification

A cloud session asked how it would act on a request to check that a change works answered with
generic steps: nothing in plumb was reached by that request, and the first consumer's verifier
lived in a product repository directory Claude Code does not load. This release gives the request
a skill, and moves the parts of verification that are not product-specific into plumb.

## What changed for users

- **`plumb:verify`** is reached first by "verify this", "does it still work", "compare against
  base" and the same request in other languages. It reads the repository's `[verify]` contract,
  hands the run to the `verifier` agent, compares with `plumb-verify compare` and reports what was
  compared and what was not. It never says pass. Without a contract it says so and runs the
  repository's own tests as tests.
- **`plumb-verify compare`** returns `regressed`, `incomplete` or `no_diff` from the observation
  rows of both sides, the thresholds and the run's manifest. **`plumb-verify plan`** says whether
  the contract is runnable.
- **Trust**: the base commit's contract, procedure and thresholds judge the head; a contract the
  head changed is a change under test. The base is chosen without reading the head and must be on an `origin` branch. A head no `origin`
  branch contains is not started.
- The browser measuring scripts, scenarios, fixtures and thresholds stay in the project (spec F).

## Compatibility

New key `[verify] thresholds` in `.plumb/project.toml`. Existing contracts without `[verify]` are
`absent` and nothing changes for them. SAKUJI's `compare.mjs` keeps working; `plumb-verify compare`
reads the same rows and thresholds.

## Verification

The comparator suite (each outcome, each incomplete cause, every rule at, below and above its
limit, precedence, malformed input, every preflight outcome, the base tree), the harness check,
the full selftest and the trigger-eval scorer fixture passed. On SAKUJI's recorded two-sided run,
the comparator agrees with `compare.mjs` (`no_diff`), and with five injected regressions it reports
the same five items with the same values.
