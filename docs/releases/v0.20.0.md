# plumb v0.20.0 - ledger views

`plumb-ledger report` prints text, and the store keeps its records in one branch per session, which
GitHub does not show as data. A task's cost could not be set against how long it took, and the work
a cloud session does on the base branch before it branches (investigation, mostly) landed in buckets
that belong to no task.

## What changed for users

- **`plumb-ledger views`** writes a README, `tasks`, `days` and `models` tables (Markdown for
  reading, CSV for every row) and `sessions.csv` into a directory. In the store's default branch they
  can be read on GitHub without running anything. The command never pushes and writes only under
  `--out`.
- **Active time** is measured per session: consecutive requests at most 30 minutes apart
  (`--gap-minutes`) are one stretch of work, and the interval is credited to the task of the later
  request. Long gaps are idle and count nowhere. Parallel sessions on a task each add their own time;
  the task's span is shown beside it.
- **Session attribution**: capture now records `remote_session`, the cloud session id also carried by
  `Claude-Session:` commit trailers. With `--changes` (from `plumb-ledger changes`), a request on the
  base branch or with an unknown branch goes to the one landed pull request its session produced. A
  session that produced several leaves it where it was, counted. A request with no repository is moved
  when its session produced exactly one pull request across all repositories. `report` accepts the same
  option, and `--repo` filters on the repository a request was placed in.
- **`docs/ledger.md`** gives an example daily workflow for the store (views of the trailing 28 days
  into `views/latest/`), and `plumb:retro` keeps each week's views and its notes in the store.

## Compatibility

Records gain one field, `remote_session`; records captured before have none and read as null, and
nothing is backfilled. The field is one identifier that commits already carry publicly. No config key
changed. `report` output is unchanged unless `--changes` is given.

## Verification

The new `scripts/test-ledger-views.py` (the field and its null cases, the gap just under, at and over the
limit, parallel subagents, a branch switch, one, no and several pull requests for a session,
byte-identical output, escaping, writing only under `--out`, the store-only run), the existing
ledger suites, the harness check and the full selftest passed.
