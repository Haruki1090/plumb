# plumb v0.27.0 - see what is waiting with `plumb-stalled`

Nothing listed what was waiting. A survey of 50 merged pull requests in one repository found most of
the time between opening and merging was spent in draft with no commit for two hours or more, and
several sat for most of a day with their checks already passed but not marked ready. `plumb-run-view`
shows only the pull requests a lead ledger points at.

## What changed for users

- New command `plumb-stalled [--repo <dir>] [--idle-hours 2] [--verified-pattern <regex>]
  [--promoted-ref <ref>] [--promoted-limit 50] [--json]`. It reads the open pull requests from the forge
  in one call and prints a table, oldest first inside each group: `verified-not-ready`,
  `ready-unmerged`, `draft-idle`, then a count of `draft-active`. `--json` prints the same document.
- The clock of a draft is its newest commit with fewer than two parents: merging the base branch in does
  not make a pull request look active. A ready pull request is timed from when it was marked ready.
- `--verified-pattern` is a regular expression whose first capture group is a commit SHA (7 or more hex
  characters). A draft is `verified-not-ready` only when the captured SHA is a prefix of its current
  head; a match for an older head, or one inside an HTML comment, does not count. Without the flag that
  group is absent.
- `--promoted-ref` lists the newest `--promoted-limit` merged pull requests into the base branch
  (`plumb-project repo.base_branch`, else the open pull requests' most common base, else the default
  branch) whose merge commit is not an ancestor of that local ref. Nothing is fetched: a ref or a merge
  commit that is not in the clone makes the answer `unknown` with the reason. When the limit is reached
  and the oldest one checked is itself unpromoted, the table says the count is a lower bound.
- `plumb-stalled` calls no model, keeps no state, caches nothing and writes nothing. When the forge is
  unreachable or slow (10 seconds in all) it prints `remote: unavailable` and exits 0; only a bad
  command line exits non-zero. Control characters in titles and logins never reach the terminal.
- `plumb:lead` names `plumb-stalled` in triage when the queue is pull requests.

## Do you need to do anything

No. The command is new and nothing else changes. To see the two optional groups, pass the repository's
own evidence line as `--verified-pattern` and the ref merged work is promoted into as `--promoted-ref`;
neither is built in or read from the project contract.

## Verification

- `python3 -B scripts/test-stalled.py`: a base merge does not reset the clock, the all-merges fallback,
  the idle threshold boundary, `ready_at` from the event, a stale SHA and an HTML comment do not verify,
  unpromoted by ancestry, `unknown` for a missing ref or commit, the lower bound at the limit, an
  unreachable forge, control characters in the table, and that nothing is written.
- `bash scripts/selftest.sh`.
- `bash scripts/check-harness.sh`: the versions and this note agree; the remaining NG lines are the
  proper-noun check on addresses in existing test files, as before this release.
