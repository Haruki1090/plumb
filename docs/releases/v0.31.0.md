# plumb v0.31.0 - a second reading of upstream

plumb was read against its upstream again and took what it had been missing. `docs/scope.md`
records each decision; the changelog lists every change.

**Verification can start from nothing.** `plumb:verify-init` writes a repository's first `[verify]`
contract and claims nothing it did not see run. `plumb:verify` keeps the feature map true on request.

**Numbers and premises get checked.** `principle-explain-the-number` asks seven questions of a
measured number before it enters a claim. `principle-attack-the-premise` fires on the second fix
that fails at the same gate. A safety claim now carries a rung saying how far it was checked.

**Less is taken on trust.** `plumb-lane stale` finds lanes that stopped, from recorded facts.
`plumb-decision-log --audit` resolves the commits, pull requests and files a log cites.
`plumb-pr-watch` gives a pull request's state as one word and an exit code, and unknown data is
`pending`, never `ready`. `plumb-check-pr-body` checks a body mechanically.

**The owner's side has skills.** `plumb:catch-up`, `plumb:recall`, `plumb:reflect`, `plumb:help` and
`plumb:configure`, and five guide pages under `docs/guide/`.

**A merge below production can be the coordinator's.** With `repo.production_branches` in the base
branch's contract, `plumb:lead` may merge a lane's pull request into a branch that is neither listed
nor the default branch, once an independent verdict names the current head. Without the key nothing
changes: it stops at a ready pull request.

Nothing here changes behavior until it is asked for: the new contract key, the `worker.rules.types`
hook and the exception columns are all optional.
