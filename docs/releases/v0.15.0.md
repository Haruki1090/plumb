# plumb v0.15.0 — the work ledger and cost per task

plumb can now say, with numbers, which landed changes were fixed later and what each task cost on
which models, without writing anything to the product repository.

## What changed for users

- **`plumb-ledger changes` and `rework`** read a repository's landed pull requests and direct commits
  over GitHub REST and the local clone, and compute the rework rate for the authors the project
  contract names: pending windows are reported, not counted clean.
- **Cost capture is opt-in.** With `ledger.capture = on`, plumb's first hook (`Stop`) records each new
  request's tokens and attribution at the end of the turn, in the background. With it off, the hook
  returns in about 10 ms without starting Python.
- **`plumb-ledger export`** pushes each session's records to a private repository you name
  (`ledger.store`), one ref per session, so a cloud session's records survive its container.
- **`plumb-ledger report`** gives cost by task, model, frontier share, role and token kind, the cost
  of reworked changes, and what is unknown or not yet exported.
- **`plumb-doctor`** reports capture and the store preflight.
- **`docs/ledger.md`** has the records, the allowlist and the rules.

## Compatibility

Additive. Capture is off unless `ledger.capture = on`; without a store, records stay local. GitHub
lists are paged by number because `gh api --paginate` fails behind a cloud session's proxy.
`session-audit`'s output is unchanged.

## Verification

`scripts/check-harness.sh` and `scripts/selftest.sh` pass, and selftest now runs both ledger suites.
They cover merge, squash and rebase landings, pagination, a shallow clone short of the period, a
hand-computed rework rate, branch attribution (a branch switch inside a turn, a worktree subagent, a
removed worktree, a detached HEAD), unique task assignment, forked transcripts, Codex ids, id
conflicts, unknown cost, exact sums, concurrent and repeated exports, an unreachable store, and the
hook's latency (off and on). `plumb-ledger changes` was run against a real repository's three days
of history (45 pull requests), and capture against a real session (441 requests from 1,022 records).
