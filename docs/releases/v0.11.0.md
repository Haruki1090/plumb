# plumb v0.11.0 — measure the coordinator

v0.10.0 shipped `plumb:lead` with no way to tell whether it worked. This release adds one, and the
first measurements changed the skill.

The evaluation follows four axes: does the skill fire, does it follow its process, is its output
right, and what does it cost. It runs in three stages, from cheap to expensive: a trigger eval, a
dry run on the real queues with writes denied, and a live trial to ready PRs. A defect the cheap
stage can catch is not carried into the expensive one.

## What the measurements found

**Firing.** On the two models that hold the coordinator seat, PR-queue asks did not start the
skill. After the description was rewritten to lead with them, precision is 1.00 on every set, and
recall is 1.00 on the owner's own phrasing on both models (0.83 on the English set on one model).

**Process and cost.** A dry run on a real product repository's queues (43 issues, 7 PRs) ran each
queue three times, with the working tree, HEAD and stash compared before and after. Issue triage
agreed with an adjudicated golden table on 70–77% of items at $2.7–3.6 per run; PR triage on
86–100%. Against a copy without the skill, triage accuracy was indistinguishable; what the skill
changed was process — the ledger, the merged-PR search, the queue kept to the owner's PRs instead
of every open one — and 20–30% lower cost.

**Garbage in.** The first golden table was itself wrong. Of the 21 items where it disagreed with
the skill, it was wrong on 17. The disagreements were adjudicated blind before anything was scored.

**Garbage out.** Two runs of three called an open PR `landed` on an ancestry claim that a single
command disproves. The PR rule now requires that command and its result on the ledger.

**Live trial.** Two issues, two lanes, one coordinator session: both reached ready PRs with green
checks in about 14 minutes, 11 of 11 process checks, $3.63 for the coordinator. The coordinator
widened one lane to restore a guard its test depended on; the widening was right, but it was
visible only in the PR title. A lane that does work its item never named now says so in the report
row and the PR body.

The grader's first pass on the trial flagged five failures; four were the grader's own (a relay
script's stop pattern read as a force push, a retried worktree read as a third lane, briefs written
through a heredoc not counted). They are fixed, with regression cases.

## Compatibility

Additive for users of the skill. The new tools run only when called.

## Verification

Harness check and selftest passed; the synthetic regression suite covers both graders.
