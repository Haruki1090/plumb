# plumb v0.26.0 - lead: see a running queue again with `plumb-run-view`

After a compaction or a resume, a `plumb:lead` coordinator had only its ledger to rebuild the queue
from: which lanes exist, which pull request each opened, what already landed, what is left. The ledger
says what the coordinator believed; the forge says what happened, and the two were joined by hand.

## What changed for users

- New command `plumb-run-view [--repo <dir>] [--ledger <file>]... [--since <hours>] [--no-remote]`. It
  reads the `lead-*.tsv` ledgers in `plumb-path run` whose last row is within `--since` (default 12 hours)
  and prints one JSON document: for each ledger its lanes (state, since when, done, needs the owner, the
  linked pull request with its state and checks), the events of the run in time order, and the items
  that remain with their next step. A pull request that is merged or closed makes its item done
  whatever the ledger says.
- An item is linked to a pull request by two rules only: its latest `ref` cell (`pr:<number>`, or
  `branch:<name>` for the newest pull request with that head branch), else an item cell that is wholly
  `#<number>` when that number is a pull request. A number in `evidence`, `next` or the middle of an item
  is never read. The `evidence` cell is never printed.
- `plumb-run-view` calls no model, keeps no state and caches nothing. With `--no-remote` it does not ask
  the forge; when the forge is unreachable or slow (10 seconds in all) every pull request is null and
  `remote` says `unavailable`. Either way it exits 0 with valid JSON; only a bad command line exits
  non-zero.
- `plumb:lead` opens its ledger with a seventh column, `ref` (`branch:<name>` on the row that starts a
  lane, `pr:<number>` on the row that opens or names its pull request, `-` otherwise), and step 5 points
  at `plumb-run-view` for resuming.

## Do you need to do anything

No. A ledger without the `ref` column still reads (every item then links only by its own `#<number>`),
and `plumb-lead-grade` grades both headers. To get the links for a branch-first lane, let the next
`plumb:lead` run open its ledger with the new header; a ledger already open keeps its old one.

## Verification

- `python3 -B scripts/test-run-view.py`: link rules (a number in prose is never linked), check
  classification, done by fact, `needs_owner`, `since`, `late`, events ordering, unknown headers,
  `--no-remote`, an unreachable forge, empty run directory, determinism.
- `bash scripts/check-harness.sh`: the new text names no routing target and only a command in `bin/`.
- `bash scripts/selftest.sh`.
