# plumb v0.16.0 — the improvement loop

The work ledger and the cost per task (0.15.0) now feed a loop: failures are recorded one way,
looked at weekly, and each one is taken to the layer that stops it, with a number that shows
whether it did.

## What changed for users

- **`docs/failure-taxonomy.md`** defines the failure record, the codes C01–C15 and the layers.
- **`plumb-ledger failures`** collects the records of a repository and period.
- **`plumb:retro`** is the weekly look back; **`plumb:failure-to-rule`** works one failure out.
- **`evals/improvement-loop/`** has their trigger cases and a worked example from a real failure.

## Compatibility

Additive. Nothing runs unless asked; neither skill changes code, labels, issues or pull requests by
itself, and a repository CI rule is only ever proposed.

## Verification

`scripts/check-harness.sh` and `scripts/selftest.sh` pass, and selftest runs the failure collector's
suite. The trigger cases are run with `plumb-trigger-eval`.
