# plumb v0.32.0 - prose, comments and the description budget

Upstream pstack 0.15.48 was read; its one new skill, `reframe`, is folded into
`playbooks/shaping-the-work.md`. The changelog lists every change.

**Prose has numbered rules.** `docs/writing.md` (W1-W20) and `docs/writing-ja.md` (J1-J23) cover
reports, pull request bodies, commit messages and documents in English and Japanese. The router and
`playbooks/opening-a-pr.md` point at them, and a review can cite a rule by its id.

**Comment blocks and commented-out code can be refused.** `[code_policy]` takes `comment-block`
(a run of at least `min_lines` added comment lines) and `commented-code` (an added comment whose whole
body is one statement). Short explanatory comments pass. When unsure, `commented-code` does not fire,
and its known misses are listed in `docs/project-contract.md`.

**Skill descriptions have a budget.** Rule 16 of `check-harness` holds the descriptions of every
model-invoked skill to 7,700 bytes (7,675 today), so a new skill or a longer description has to take
its bytes from another one.

Nothing changes in a repository until its `.plumb/project.toml` adds the new rule kinds.
