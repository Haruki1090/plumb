# Working with plumb: a guide

The other documents in this repository say what plumb is and how its parts fit. This guide is about
you: what to type, what a good request looks like, and what to do when something goes wrong. It is
written for the owner of a repository who works with plumb through a coding agent.

Read the pages in order the first time. Afterwards, go straight to the page you need.

1. [A first hour](01-first-hour.md): check the install, make three settings, and finish one small task from prompt to evidence.
2. [Asking well](02-asking.md): what a request carries, what to leave out, and three weak requests rewritten.
3. [Recipes](03-recipes.md): twelve situations, the prompt to paste for each, where it lands and what comes back.
4. [Leaving a run overnight](04-overnight.md): what to settle before you go, when to trust a loop, and what to read in the morning.
5. [Pitfalls](05-pitfalls.md): symptom, cause and remedy for the failures that actually happen, each tied to a tool that exists.

Installation and the configuration file are described once, in the [README](../../README.md). Where each
role runs is in [docs/role-map.md](../role-map.md), and the repository's own contract is in
[docs/project-contract.md](../project-contract.md).

The prompts in this guide are examples. Change the nouns, keep the shape. Each page also shows one prompt
in Japanese: plumb works from a request in either language, and the structure it returns stays in English.
