# ヒルクライム

**指標と実験の健全性を持つのはあなた。**監督とレビューをし、試行は委譲する。

測れるもの一つを、目標に向けて継続的に改善する仕事。「起動を50%速く」
「この指標を系統的に下げ続けて」。一発の修正は `playbooks/perf-issue.md`。**これはループ。**

中核の規律は一つ。**1変更・1計測・採用か取り消しか。**未検証の変更を積まない。
コードを読んだだけで勝ちを主張しない。**データが決める**（**principle-prove-it-works**）。

1. 定規を選ぶ前に、対象と現実の負荷を掴む。結果を動かしうる次元（データ量、履歴、状態、並行度）を
   名指し、持ち主の訴えを再現する条件を選ぶ。**再現する条件が無いなら、ヒルクライムではなく
   再現を直す。**そのうえで、指標1つ、良くなる向き、そして停止述語を決める。
   **停止述語は目標と試行回数の下限を対にする**——「基準比50%以上、かつ10試行以上」の形。
   幸運な早い当たりで run が終わらないようにするため。
2. 計測の道具を作り、感度を証明してから凍結する（**principle-build-the-lever**）。
   対照的な負荷を走らせ、狙った条件が症状を再現し、易しい条件が分離することを確かめる。
   **定規が両者を区別できないなら、負荷か指標を作り直す。**
   凍結後は、繰り返し可能な1コマンドが指標を吐く。雑音を超えるまでサンプルを取る（1回ではなく N の中央値）。
   **変えたら過去の数字が全部無効になる。**
   最初の変更の前に、基準値と、緑の退行ゲート（通り続けねばならないテスト）を記録する。
3. 決定ログを開く。**最初の試行の前に。**

   ```bash
   plumb-decision-log <ログ> --header id 仮説 変更 前 後 差 テスト 判定 備考
   plumb-decision-log <ログ> 1 "<仮説>" "<変更>" 1200 940 -260 green 採用 ""
   ```

   手で書かない——列がずれ、タブが混ざり、根拠に入った文字列が表計算で数式として走る
   （道具側で無害化してある。**素の数値は素通しなので、前・後・差はそのまま並べ替えられる**）。
   **これが run の記憶。**各試行の前に読む。読まないと探索が積み上がらず、同じ場所を回る。
   取り消しを跨いで生き残るよう、ツリーの外（gitignore 下）に置く。
4. 各仮説を手順1の構造理解に接地させ、**具体的な機構を名指す**。
   「初回描画を塞ぐので X を起動経路から外す」。「何かメモ化してみる」は仮説ではない。
5. 1試行1仮説で回す。
   - 変更は実装役に狭い範囲で渡し、**自分では打たずに差分をレビューする**
     （**principle-guard-the-context-window**）。独立な仮説が複数あるなら並列に投げ、
     衝突しないよう別々の worktree に置く（**principle-separate-before-serializing-shared-state**）。
   - 凍結した道具で前後を計測し、退行ゲートを走らせる。
   - **指標が雑音を超えて動き、かつゲートが緑のときだけ採用。**それ以外は変更を全部取り消す。
     「効くかもしれない」調整の相乗りは無し。
   - 採用1件につき1コミット。触ったファイルだけを stage する（`git add <files>`、`-A` は使わない）。
     採用でも取消でも行は記録する。
6. 最初の停滞を越える。数回続けて落ちたら、カテゴリを変える、惜しかったものを組み合わせる、
   ソースを読み直す、もっと過激な案を試す。**正しさと単純さは数字より上。**
   振る舞いを壊した勝ちは取り消し、数字を保つ単純化は残す（**principle-laziness-protocol**）。
7. 述語を満たしたら止める。**勝利宣言のために述語を緩めない。**

   **未達で止めるには、述語と同じだけの厳しさを通す。**「残りは僅少だと思う」では止まれない。

   - **試行回数の下限に達していること。**達していないなら、止める資格が無い。
   - **残っている案を全部書き出すこと。**各案に、なぜ効かないと判断したかを 1 行。
     **その 1 行は、次のどちらかでなければならない。**
     (a) 決定ログの既存の行を指す——同じ機構を狙った試行が既に落ちている。
     (b) 手順 1 の構造理解に接地した機構の理由——「この経路は全体の N% しか占めない」。
     **「たぶん効かない」「筋が悪そう」は理由ではない。**
     書き出せないなら、それは「僅少」ではなく「考えていない」。
   - **未達での停止は、判定役に通すこと**（`docs/role-map.md`）。
     残案の一覧と切り捨ての根拠を渡し、**見落としが無いかを別ファミリーに問う。**
     自分で決めた目標を、自分の判断だけで下ろさない。
   - **決定ログに未達で止めた行を残すこと。**達成値・目標値・残案・止めた理由。

   **この 4 つが全部揃わない停止は、述語を書き換えずに述語を無効化することになる。**
   どれか 3 つで足りると読まない。判定役を省いた停止も、この規定に反する。
   安い未試行が残っているうちは辞めない。詰まったなら、回り続けずにそう言う。
8. 採用したコミットを着地順に積み、`playbooks/closing-a-branch.md` で締める。
   **PR を出すと決まったら** `playbooks/opening-a-pr.md` へ。指標の登りが上から下に読める。

**返すもの:** 指標と目標、基準から最終までと変化率、試行数（採用/取消）、
採用した修正を各1行、決定ログのパス、もっと押すなら次に試す最良の案。
