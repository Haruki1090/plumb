# 計画を回す

**計画を実行するのは、この会話を読んでいない者。回す側は、その者を毎回新しく立てる。**

`playbooks/writing-a-plan.md` が出した計画を、タスク単位で着地させる。
**形を決め直す場所ではない**——欠陥が出たら裁定して記録して進む（下の「止まる線」）。

夜を跨ぐなら `playbooks/autonomous-run.md` を重ねる。**終了述語・起こし方・
反復ごとの記録はあちらの領分**で、ここには書き写さない
（**principle-encode-lessons-in-structure**）。

## 0. 配るか、本線が刻むか

**渡し方の表は `playbooks/writing-a-plan.md` の手順7が正本**で、ここには書き写さない。
選ばれていないなら、そこを読んで決めてから戻る。既定は**配る**——
1タスク1役にすると、**かさばるものが本線に載らない**
（**principle-guard-the-context-window**）。タスクが3つ以下か互いに強く絡むなら本線が刻む。

**タスクを同時に配らない。**計画のタスクは同じツリーの同じ面に書くので、
`playbooks/fan-out.md` の手順1の判定がそのまま否と言う
（**principle-separate-before-serializing-shared-state**）。
肯と出るほど独立しているなら、それは計画の実行ではなく fan-out。あちらへ行く。
以下は配る側の手順だが、**本線が刻む場合も 2〜6 の関門は踏む**——
配らないことは、関門を飛ばす理由にならない。

## 1. タスク1を配る前に

**台帳を先に作る。**

    log="$(plumb-path run --mkdir)/$(basename <計画のパス> .md).tsv"
    plumb-decision-log "$log" --header タスク 状態 起点 到達 指摘 裁定
    plumb-decision-log "$log" 0 開始 "$(git rev-parse --short HEAD)" - - "<計画のパス>"

**機構を発明しない。**台帳は `plumb-decision-log`、置き場は `plumb-path run` で足りる
（**principle-subtract-before-you-add**）。**ファイル名は計画から取る**——別の計画の台帳を
自分の進捗と読み違えると、**終わったタスクをもう一度配る。**
**圧縮で記憶が消えても台帳と `git log` は残る。**再開したら、記憶ではなくそちらを信じる。

**計画を1度だけ読む。**全体制約を控え、タスクごとに todo を立てる。
spec のパスが書いてあるなら spec も読む——**裁定で勝つのは spec のほう。**

**そのうえで、計画の中の矛盾を先に洗う。**同じファイル・同じ面を触るタスクの組を並べ、
片方が作るものと他方が使うものを突き合わせて、**組ごとに1行書く。**
「読んだが綺麗だった」は行を書いていない（**principle-gate-claims-on-evidence**）。
見つけた矛盾はここで裁定して台帳に残す。**実行が始まってから直すと、そこまでが全部ずれる。**

## 2. 1タスクを配る

**配る前に起点を記録する。置き場はシェル変数ではなく台帳**——
変数は圧縮を跨がないが、台帳は跨ぐ。

    plumb-decision-log "$log" 3 配布 "$(git rev-parse --short HEAD)" - - -

**あとで `HEAD~1` を起点にしない。**タスクが2コミット以上になった瞬間、
最初のコミットが関門に載らずに落ちる。**落ちても赤くならない。**

渡すものは3つで、**全部ファイルにして渡す**（**principle-guard-the-context-window**）。

- **ブリーフ。**そのタスクの本文だけを切り出した1枚。**計画ファイルごと読ませない**——
  隣のタスクを読んだ実装役は、隣の仕事を始める
- **報告の書き先。**詳しくはそこへ書かせ、**戻り値は状態と成果物だけ**にする
- **先行タスクが実際に置いた面。**関数名・型・実在のパス。ブリーフに書けないのはこれだけ

**前のタスクの経緯を貼らない。**貼ったものは以後の全ターンで読み直される。
渡し方の残り（範囲・判断材料・触ってはいけないもの・返す形）は
`playbooks/fan-out.md` の手順2が正本。

**同じ形の小さいタスクが並んでいるなら、1通にまとめて配る。**
同じ1行の修正が5ファイルに散っているのは、5つの仕事ではない。

**実装役にレビュー役を立てさせない。**向こうが立てた席は同じ差分を二度読むだけで、
**判定として数えない。**関門はこちらの席。

## 3. 返ってきたものを扱う

引っかかりを添えて返ってきたら、**中身を読んでから進む**——正しさか範囲に関わるなら、
関門の前に片付ける。文脈が足りないと言うなら補って配り直す。

**詰まったと言われたら、同じ条件で撃ち直さない。**文脈を足す／タスクを割る／
計画を裁定する／役を替える。**何も変えずに再送するのは、無視と同じ。**

## 4. 関門を通す

**自己申告を関門の代わりにしない**（**principle-gate-claims-on-evidence**）。
実装役の自己点検は本人の目であって、判定ではない。

**差分はファイルで渡す。**本線の文脈に差分を載せない。

    from=<台帳に書いた起点>
    pkg="$(plumb-path run)/task-3.diff"
    git log --format='%h %s' "$from"..HEAD  >  "$pkg"
    git diff --stat          "$from"..HEAD >> "$pkg"
    git diff -U10            "$from"..HEAD >> "$pkg"

渡すのはブリーフ・実装役の報告・差分ファイルの3つのパスと、
**計画の全体制約を逐語で写した数行**。制約がレビュー役の視線を決める。

- **「ここは指摘しないで」と書かない。**先回りの判定。挙げさせてから裁定する
- **実装役が回した検査を回し直させない。**証拠は報告のほうにある
- **「差分からは確かめられない」と返ってきた項目は、こちらが片付ける。**
  タスクを跨ぐ要求にレビュー役の手は届かない。本物の穴なら、関門の不合格として扱う

## 5. 直しの周回に上限を置く

**直すのは実装役。本線が自分で直さない**——本線が入れた差分は、関門を一度も通らない。

- **1〜2周は同じ役に返す。**指摘を逐語で渡す。文脈が生きているぶん速い
- **3周目は別の役を立て直す。**報告ファイルを渡し「前の者が2回試して届かなかった」と言う。
  **3回返して収束しないのは、その役が自分の穴を見られないということ**
- **そこで打ち止め。**

上限に当たったら、**残った指摘を1件ずつ自分で裁定して、台帳に書く。**

| 残った指摘 | どうするか |
|---|---|
| 指摘のほうが違う／争いがある | **据え置く。**理由を書く。最後の全体レビューが両論を見る |
| 本物だが、後続が乗らない | 据え置く。**本物だと書いたうえで**据え置く |
| 本物で、後続が乗る | **後続が進む最小の直しを決めて、次のタスクに持っていく** |

**裁定は上限に当たってからだけ。**周回を早く畳むための先回りは、名前を変えた握り潰し。
**台帳に無い指摘は、存在しなかったことになる。**

軽微な指摘は周回に入れず、**台帳に行を足して最後の全体レビューに向ける。**
向け先を書かない「後で見る」は、捨てたのと同じ。

## 6. タスクを閉じる

閉じてよいのは、**関門が通ったか、上限で全件に裁定が付いたか**のどちらかだけ。

    plumb-decision-log "$log" 3 完了 "$from" "$(git rev-parse --short HEAD)" "重要0/軽微2" -

**タスク1つにつき、配布で1行・周回ごとに1行・完了で1行。**
完了行の無いタスクは、再開したときに未着手として扱われる——
**跡の無いタスクは、もう一度配られる。**

## 7. 全部終わったら

**ブランチ全体を、一度だけレビューに通す。**タスクごとの関門は範囲がタスクに閉じていて、
**繋がって初めて出る失敗はそこを通っていない**（**principle-sequence-verifiable-units**）。
台帳の据え置き行と軽微の行を、そのレビューに向ける。

指摘が出たら、**1通にまとめて1回だけ直す。**指摘ごとに役を立てると、
各々が文脈を作り直して検査を回し直す。直したら範囲を絞って1回だけ見直す。**波は1回まで。**
残ったものは 5 と同じ形で裁定し、台帳に置き、**返答に載せて持ち主へ渡す。**

行き先は `playbooks/closing-a-branch.md`。途中で PR を出すなら `playbooks/opening-a-pr.md`、
その指摘に応じるのは `playbooks/being-reviewed.md`。

## 止まる線

**回している間は人を待たない**（**principle-never-block-on-the-human**）。
衝突も、曖昧さも、計画の欠陥も、**決めて、台帳に書いて、進む。**
外した裁定は差分1本で戻せる。**問いを立てて止まった夜は、何も戻せない。**
進捗の報告や「このまま続けていいですか」では止まらない。

止まるのは4つだけ。**取り消せない操作**（消す、流す、本番に触る）。
**この作業場の外に出る副作用**（共有ブランチへの push、merge、公開）。**鍵や権限に触る変更**。
**計画の欠陥が「形」まで届いていて、どの道も当てずっぽうになるとき。**

4つ目は `playbooks/shaping-the-work.md` の「取り消しの値段」と同じ線。
**手の側なら決めて進む。形の側なら止まる。**

**返すもの:** 台帳のパス、タスクの本数と各々の起点・到達コミット、周回に入ったタスクとその回数、
**自分が下した裁定の全部**（何を、なぜ、外していたら何を失うか）、据え置いた指摘、
全体レビューの結果、次に入る型。
**裁定の一覧を出さない run は、持ち主に黙って決めたのと同じ。**
