# A decision the owner can make

State the decision and what changes with the answer. Compare the viable options against the same real axes: behavior, scope, cost, operational consequences, or concrete examples. Show the recommendation and its evidence without thinning out the alternatives.

Use a compact table for a simple choice. For a complex or visual comparison, create a standalone HTML brief using the requested style. A local artifact is sufficient unless publishing is requested; unavailable artifact hosting does not block the decision.

Ask with the runtime's available user-input tool or one concise question, using the same option labels as the comparison. Do not ask for facts that can be established from the scoped material, or re-ask a choice already made. A progress report, a single viable path, or a yes/no permission check does not need this workflow.

After asking, continue independent work while the decision is pending. Do not implement the branch that depends on an unanswered choice. On receipt, execute the chosen result and record durable decisions in the existing plan or decision log when relevant.
